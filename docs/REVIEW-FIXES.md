# Independent review — fix report

Every finding was reproduced by a regression test written before the fix, with an expected value
derived from the file-format spec, a hand-seeded generator, or arithmetic in the test. Build is
clean with `-warnaserror`; the full suite passes on net8.0 and net10.0.

| Finding | Regression test | Fix summary | Status |
| --- | --- | --- | --- |
| CRITICAL — corrupt/out-of-bounds checkpoint page silently becomes "absent" (count 1000 → 0, loss made permanent by next checkpoint) | `CheckpointCorruptionTests.CorruptVectorPage_DefaultOpen_ThrowsAndNeverMutatesTheFile`, `OutOfBoundsPageOffset_ThrowsCorruptionException` | `Checkpoint.Read`/`ReadVectorOffsets` validate bounds and CRC32C and now throw `FaroCorruptionException` by default. Added `CheckpointRecovery`, `CorruptionReport`, `FaroDb.OpenWithRecovery` and `FaroDb.RecoveryReport` for explicit salvage that reports each skipped region and never mutates the files during a failed strict open. | Fixed |
| HIGH — concurrent `Upsert` on the same key races TryGetValue/AddCore (200 keys → hundreds of live nodes) | `ConcurrentUpsertTests.ConcurrentUpsert_SameKey_IsAtomic` | Striped per-key gates in `FaroDbCollection` serialize the whole key→id read/modify/write (and `Delete`); fixed stripes keep memory bounded. 200 keys now produce exactly 200 live nodes/keys and 50 distinct top-50 hits. | Fixed |
| HIGH — Batched records trapped in the 64 KB FileStream buffer; FailFast crash loses them; `None` docs inaccurate | `WalDurabilityTests.BatchedBatch_SurvivesFailFastCrash` (child process killed with `Environment.FailFast`), `CorruptWalHeader_ThrowsByDefaultAndSalvageKeepsOriginalBytes` | `UpsertBatch` now fsyncs at the batch boundary; Batched appends also flush every 256 records. `Durability.None`, `FaroOptions`, `docs/file-format.md` and README now state that process crashes lose recent commits. | Fixed |
| HIGH — searches skip the gate; checkpoint disposes the mapping under them (`ObjectDisposedException`, unmapped reads) | `SearchCheckpointConcurrencyTests.ConcurrentSearchAndCheckpoint_NeverThrows` | `Search`, `HybridSearch`, `GetByFilter`, `TryGet`, `ContainsKey`, `Count`, `Keys` and `Compact` hold the database read gate; the checkpoint's write gate waits before releasing/remapping the vector pages. Docs updated. | Fixed |
| HIGH — `Restore` calls `Compact()`, discarding the stored graph (82.6 s reopen vs 0.14 s checkpoint) | `HnswRestoreTests.Reopen_LoadsStoredGraphWithoutRebuilding` | `Restore` loads adjacency pages as-is and completes asymmetric WAL edges with a linear reciprocal pass instead of rebuilding. Added `RestoredFromStoredTopology` and a reopen perf bound; `docs/file-format.md` updated. | Fixed |
| MED — `File.ReadAllBytes` + `checked((int)offset)` prevents opening files > 2 GB | `CheckpointCorruptionTests.OutOfBoundsPageOffset_ThrowsCorruptionException`, `RealisticPersistenceTests.ByteFlipsAndTruncations_NeverYieldSilentlyDifferentData` | Checkpoint header, page table and pages are read through a `FileStream` using `long` offsets and lengths; only individual pages are materialized. | Fixed |
| MED — README persistence sample does not compile (int-keyed collection + string-key `Upsert`) | `ReadmeSampleTests.DatabaseSample_Compiles`, `AllReadmeSamples_AvoidMismatchedKeyTypes` | README.md and README.pt-BR.md use `GetOrCreateCollection<string, Doc>`. The Roslyn test reads the actual README block and compiles it with hand-written stubs. | Fixed |
| WAL header corruption wipes the whole log | `WalDurabilityTests.CorruptWalHeader_ThrowsByDefaultAndSalvageKeepsOriginalBytes` | Strict mode throws `FaroCorruptionException` and leaves bytes untouched; salvage copies to `<path>.wal.corrupt`, reports the issue and starts a fresh valid header. Short headers remain torn-tail (crash before first append). | Fixed |
| Replay skips a CRC-valid but malformed record and applies later records | `WalDurabilityTests.StructurallyInvalidRecord_StopsReplayAtLastValidPrefix` | `FaroDb.Replay` records the issue and breaks, so only the last valid prefix is applied. | Fixed |
| `Replace` keeps the old topology after a vector update | `HnswRestoreTests.Replace_RelinksGraphToNewVectorPosition` | `Replace` now detaches the node from all layers and re-connects it with the same layered search + Algorithm 4 selection used by inserts, repairing its spine neighbours. | Fixed |
| SIMD kernels only `Debug.Assert` lengths before `LoadUnsafe` | `KernelLengthValidationTests.*` | Float/int8/bit kernels call `RequireSameLength` at runtime (inlined throw helper) in both Debug and Release, before any unsafe load. | Fixed |
| Tests used tiny 16-d one-hot data | `RealisticPersistenceTests.RandomizedHighDimension_CheckpointRoundTrip_IsBitExact` | 200 × 128-d splitmix64 vectors round-trip through checkpoint with bit-exact equality against test-generated values. | Fixed |
| No corruption fuzzing of persisted files | `RealisticPersistenceTests.ByteFlipsAndTruncations_NeverYieldSilentlyDifferentData` | Byte flips in every page kind plus header/page truncations: opening either yields the exact original data or throws an I/O corruption error — never partial data. | Fixed |

Total: 13 findings, 13 fixed. Full suite: 1338 passed, 0 failed (net8.0 + net10.0).
